New feature in design/discussion phase as of 2026-08-26, player-facing name **"Category Blitz"** (internal/file shorthand can stay NAPT — Name/Animal/Place/Thing). Daily/Solo/Versus sub-modes. Core mechanic: spin wheel for a letter (all 26, no exclusions), fill category inputs in 1 minute, auto-check against offline-built wordlists (same pattern as `scripts/generate-wordle-hints.js`), self-report fallback for unrecognized words.

Decisions locked in during the 2026-08-26 discussion (nothing implemented yet):

- **4 categories, not 5**: dropped Fruit/Vegetable for v1 — Name/Animal/Place/Thing is the classic recognizable format, keeps the 1-min timer less rushed. Fruit + v2 categories (Celebrity/Movie/Song/Brand) deferred together, architecturally trivial to add (just another wordlist file).
- **Answer matching**: exact match only (no fuzzy/edit-distance), case-insensitive — normalize both typed input and wordlist entries via trim+lowercase at build time and check time.
- **Timer stats**: Daily records `elapsedSeconds` at submit alongside score (extend what `dcSaveHistory` in `assets/daily.js` already writes), shown as faster/slower vs average on result screen. Versus tie-break = lower total elapsed time across the match (not a bonus point — avoids complicating per-category score semantics).
- **Solo ad gating**: changed from "every additional spin" to every-2-rounds, same mechanism `assets/challenge.js` already uses (`safeRound % 2 === 0` → `data-rewarded-href` + `gateWebSkip`). Premium = unlimited, no ads.
- **Versus ad gating**: first round free, then 1 rewarded ad per round (gates the whole round, both players share it — not per-turn, not per-match, deliberately blocking the "long match = free play" loophole).
- **Homepage placement**: Daily variant → new card inside the existing `<h2>Daily Challenges</h2>` block in `index.html` (~line 51), rides the existing interstitial-on-game-start logic in `assets/admob.js` for free. Solo/Versus mode-picker entry → new section placed after the existing `<h2>Mashup</h2>` section (~line 67).
- **Daily letter cycling**: persist used-letters array in localStorage, same shape as `dcGetStreak`/`dcUpdateStreak` in `assets/daily.js`; reset once all 26 used.
- **Web gating (resolved)**: Category Blitz — all three sub-modes (Daily/Solo/Versus) — gets a hard web wall after 1 category answered, via the existing `isLimitedWeb()` + `webWallHTML()` + `resultAppBannerHTML()` pattern from `assets/challenge.js`. It's brand new, no existing traffic/habit to protect, so wall it from day one. Daily Trivia and Daily Wordle currently have **zero** app-push on web (verified via grep — no `isLimitedWeb`/`webWall`/`TGPromo.render` calls in `assets/daily.js` or `assets/daily-wordle.js`, unlike Challenge/Mashup/Episode which already use the soft `promo-banner.js` "more themes in the app" strip). Decision: do NOT retroactively hard-wall Daily Trivia/Wordle (risk to established SEO/streak habit, no data in hand to justify it) — instead retrofit them with the same soft promo-banner nudge Challenge/Mashup/Episode already have, since right now they're missing even that.
- **Versus custom categories**: free-text "add category" input in Versus setup; any category name with no matching wordlist file automatically has no auto-check path and falls to self-report — no explicit flag needed.
- **Streak rule**: Daily streak continues on participation (played), not on a perfect score — reuses `dcGetStreak`/`dcUpdateStreak` pattern.
- **Name**: "Category Blitz" won over "Category Sprint" and "Alphabet Blitz" — Blitz signals the timer/speed-scoring emphasis better than Sprint; "Category" (not "Alphabet") avoids implying a spelling-game mechanic and avoids confusion with the existing Wordle/Word Search modes.

**Revised 2026-08-26 (later same day, post-plan-approval)**: The original "self-report" mechanic was cut entirely as a trust-based scoring input — replaced with:
- **Daily/Solo**: no fallback prompt at all. Unmatched word = instant wrong, no interruption. ## Major session 2026-08-26 (very long, later continuation) — large-scale rework

**1. Big empirical hit-rate test exposed the earlier 98% number as misleading.** A tiny (154-word) hand-picked test gave 98%; a much bigger (~1600-word) test generated fresh via a different "40 most likely answers" LLM prompt gave only **57%**. Real, concrete findings from the bigger test (not just noise): (a) **Place was missing continents/regions entirely** (Africa, Asia, the Alps, Caribbean, etc. — never in the original category scope of countries/capitals/states/cities) — fixed for free, added a `REGIONS` list to `build-catblitz-seed-lists.js`, no API cost. (b) **Name letter-A (and likely other letters that hit the raw-count target) never got LLM-augmented** despite missing common Western names (Andrew, Anthony, Amanda, Abigail...) — because the generator's old "skip if already ≥ target" logic let a high RAW COUNT (204, mostly non-Western from the multi-country seed dataset) mask a bad MIX. This was a real design flaw in the target-based approach, not just missing data.

**2. User explicitly rejected the "most likely"/"common" framing entirely** — rebuilt `scripts/generate-catblitz-wordlists.js` from scratch: no popularity/common-language filtering, no target-based skip. New approach: for every letter, repeatedly ask for MORE real distinct entries (excluding what's already found) across up to 5 rounds, stopping early only on diminishing returns (<6 new per round). A real word can only help an exact-match wordlist, never hurt it, so exhaustive-leaning generation is strictly better than a curated "most likely" list for this use case. Also fixed the model ID to the bare `claude-haiku-4-5` (no date suffix) per current Claude API guidance — the earlier scripts used a dated `claude-haiku-4-5-20251001` variant.

Ran this new approach on **Name only** (user's explicit "start with name" instruction) — massive gains confirmed live: A 204→1441, B 41→1173, C 35→990, D 55→1269, E 60→1489, ... Q 1→886. Job was still running (letter S of 26) when this memory was last updated — check `/tmp/name-gen-v2.log` or re-run `node scripts/generate-catblitz-wordlists.js name` (resumable/idempotent, safe to re-run) to pick up where it left off. **Animal/Place/Thing/Food have NOT been regenerated with this improved approach yet** — they still only have the earlier "common"-framed pass (Place/Thing needed zero calls under the old target logic since seed data already exceeded the old low targets; unclear if they'd reveal similar mix problems under the new exhaustive approach — not tested).

**3. Cost reality check, using real Haiku 4.5 pricing ($1/$5 per 1M in/out tokens) via the claude-api skill**: everything run this session (original gap-filler + partial large test-set run + the new exhaustive Name run) totals well under $5. The exhaustive multi-round Name-only run (up to 5 calls/letter × 26 letters) is itself roughly $1-2. Cost was never actually the constraint — user's real objection was to the "most likely" methodology, not the dollar amount.

**4. Versus mode's opponent-confirm flow was scrapped and rebuilt — this was a real UX mistake, not a preference.** The original design (block on every unrecognized word with a yes/no prompt for the OTHER player, sequentially, for both players' full turns) was correctly called out as unacceptably slow. New design: grading is fully synchronous/non-blocking now — `cbGradeRound` no longer takes a `resolver` param at all (removed `cbResolveUnrecognized` from `catblitz-check.js` entirely). Each player's FULL result shows immediately after their own submit (all categories, already scored). Any category that didn't match the wordlist gets a **"Contest" toggle** (not a modal, not asking the other player anything formally) — one tap flips it counted/not-counted, defaults to not-counted. `cbRenderResult` in `catblitz-engine.js` now takes a `contestable` option and returns `{getScore, getContested}` so the caller can read the live post-contest score. A "Lock In Score" button finalizes that player's turn before moving to the next player/round. Verified end-to-end via a real Puppeteer run (not just smoke test) — final screen correctly shows "Player 2: 0→1, Player 2 wins!" with zero JS errors.

**5. Solo and Versus's web-gate merged into ONE shared lock** (user: "cant play one versus game and then play another solo game...should be one shared lock"). New shared helpers `cbGetWebPlayUsed()`/`cbMarkWebPlayUsed()` in `catblitz-engine.js`, using a single `localStorage['cbWebPlayUsed_catblitz']` boolean — playing either mode once (web/non-premium) marks it and walls BOTH modes on any subsequent visit. Removed the old independent `CB_SOLO_WEB_FREE_SPINS`/`CB_VERSUS_WEB_FREE_ROUNDS` constants entirely. Verified end-to-end via Puppeteer (`scripts/.catblitz-cache/verify-shared-lock.js`): playing 1 Solo spin sets the flag, then Versus immediately shows the wall with zero rounds played, no wheel rendered. This is separate from Daily Blitz's own once-ever-per-mode flag (`cbWebDailyUsed_blitz`) — different axis (daily content vs. repeatable play), unaffected.

**6. Answer text now shown on every result row, not just correct/incorrect icon.** `cbGradeRound`'s `perCategory[id]` is `{status, answer}` not a plain string; `cbRenderResult` renders label + actual typed word + icon/contest-button in a 3-column row.

**7. Submit-time letter-match validation added.** A non-blank answer that doesn't start with the round's letter blocks manual Submit (inline error naming the offending category) — but timer expiry always force-submits regardless, so a stuck/confused player can never get trapped.

**8. "Leave Feedback" → contact.html added to every result screen** across all 3 modes, including Versus's ROUND result screen (not just the final match screen — a match might not reach the end).

**9. Solo's own gating bug fixed** (separate from the shared-lock merge above): it was trusting a `?spin=N` URL param for the native-app ad-gate cadence, which resets to 1 on any bare-URL revisit, letting anyone bypass the every-2-spins ad gate for free.
